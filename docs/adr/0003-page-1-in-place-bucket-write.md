# e3d-io 原地改写物理页 1 的桶计数器

Transaction 提交时原地改写物理页 1：页 1 已列出的每个扩展，Bucket_Counter 抬到高于新会话索引与本批发出的每个 word1，只升不降，条目与第三字原样保留。页 1 在 `StagedSession::commit` 里、`LSPGNO` 复核之后写，先写页 1 并 sync，再写 page 0 并 sync。E3D 的 SAVEWORK 也是先抬计数器、后写会话与 page 0，但两页由离开写模式时的同一次刷盘落盘；两次写之间的 sync 是 e3d-io 的加固，因为 e3d-io 每次提交都重开文件，靠不了那一次刷盘。page 0 因此不再是 e3d-io 唯一改写的已有页。依据是 13.2 的证据（`docs/evidence/2026-10-05-s6b-bucket-evidence.md`）：E3D 只从物理页 1 发号，会复用 e3d-io 发过又删掉的号。用户于 2026-10-05 确认接受。

## Considered Options

- **不写页 1**（page 0 保持唯一提交点）：E3D 继续复用 e3d-io 发过又删掉的号。
- **新页 1 追加、由 page 0 指向**（写时复制）：E3D 发号读物理页 1，不看 page 0 的指针，无效。
- **暂存阶段写页 1**：rollback 只截掉追加页，恢复不了页 1；dry run、拒写、`Moved` 都会留下改过的页 1。
- **先写 page 0 再写页 1**：两次写之间崩溃时，会话已提交而计数器未抬，正是要消除的复用窗口。
- **按需求 13 原第 6 条把第三字清零**：e3d-io 拿到独占锁时，盘上的非零第三字只可能是崩溃的 E3D 会话留下的 claim，清零等于替 E3D 回收；E3D 自己的残留由 EXPUNGE 回收（强旁证，见证据文档补采回合）。

## Consequences

- commit 内页 1 已写、page 0 未写成时，计数器已抬、会话未提交：空掉一段号，读侧仍见上一会话；计数器只升不降，无需修复。
- 改页 1 的提交多一次 sync。
- `open_at(旧会话)` 读到的是当前页 1，退回旧会话不会退回计数器（与 E3D 相同）。
- 插入页 1 列出扩展的金样键按 11.4 的做法退役并另录；需求 13 第 6 条与 Property 27 的第三字措辞改为「与写之前相同」。
- 只有 Transaction 维护页 1；自己铸号的低层暂存 API 不维护。
