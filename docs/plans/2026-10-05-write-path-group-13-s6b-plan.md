## 实施步骤

### 1. 收口探针与独立判分

- CLI 插入、删除均显式 `--spatial off --user e3dio`，新 RefNo 只从成功报告解析；核对最新会话确由该批写入，桶计数器低于本场景已发最大 word1。前提不成立即输出无法判定，不继续得出分支结论。
- Live 保留三个 ZONE；Deleted 在下一 CLI 会话全部删除；Gap 删除前两个并保留最高编号。三例分别从新的 scratch 副本运行，顺序执行；同一例从登录到 NEW/SAVEWORK 使用同一个 TTY。
- 使用 `e3d-descriptor header` 返回的 page_size 读取完整页，按 `(word2 - 2) / 3` 计算条目数并检查边界、类型、标记。保留完整三字条目，不丢弃中间状态的第三字。持久化位置以读侧和 IB 证据为准，不猜测 page 0 的桶表指针。
- 保存源库、CLI 后、登录后、选定 owner 后紧邻 NEW 前、NEW 后、SAVEWORK 后、退出后的快照与会话链。快照复制失败、短读或两次观测间文件变化均使该观察窗口无效。用 SAVEWORK 标记块里的 Q SESSION 锁定精确会话，退出后的 latest 单独报告。
- 每例使用含运行标识的独立 BEGIN/END 标记。判分只读标记块内的 Q REF/Q SESSION 结果，要求唯一、完整且顺序正确；命令回显、数字错误号、重复块、缺结果、缺日志、驱动非零和 SAVEWORK 失败均不能通过。区分探针有效性与观察结果；观察到编号复用不是探针执行失败。
- All 通过当前 pwsh 串行启动各例。每例 TTY 超时默认 600 秒，完成标记后的退出宽限沿用 20 秒；只清理本次启动且能核实身份的驱动/E3D 进程，无法确认则记录失败。所有路径在 finally 中核对源库 SHA-256 和长度，保护范围限定于已解析的 scratch 路径。后台进程使用隐藏窗口。
- 结果 JSON 增补观察窗口有效性、拒绝原因、存活重复、历史复用、桶表各字差异和精确 SAVEWORK 会话；保留现有报告字段的含义。每次运行保留独立目录，生成路径、长度和 SHA-256 清单。完整库快照留在证据归档，仓内保存可核验的页片段、日志、报告和清单。
