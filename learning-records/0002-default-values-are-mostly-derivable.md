# 默认值不用去挖 IDA 值池，目录字段能推出 88%

`all_attr_info.json` 的 `default_val` 按 `att_type + DEFI + DFDP + SIZE` 分组，
**87.72% 的属性能唯一确定**。`DEFI` 只有四个取值（0/1/4/5），是选择器不是值。
真正推不出来的只有 54 个属性，全都是 `DOUBLE` 标量的非零默认值（`ANGL=90.0`、
`TEMP=-100000.0` 这类），一张硬编码表就能补齐。

这条解除了移植计划里唯一那个"可能推翻整个方案"的风险：
原计划写着"复现率低于 90% 就要回去解 IDA 的 `dword_6C21390[dword_6C21200[i-1]-1]`"。

## Evidence

- 分组实验从 `att_type` 单键的 53.40% 一路加字段到 87.72%，再加 `ITYP` 只涨到 87.87%（无收益）
- 剩余 83 个歧义里，54 个是真缺数据，约 29 个是老 JSON 自己标量/数组 tag 不自洽

## Implications

- 顺带纠正了一个规模误解：6556 是 **(noun, attr) 对**，不同属性只有 **702** 个。
  目录侧 4271 个，属性维度覆盖率 16.4%，与 noun 维度的 16% 巧合一致。
- 679/702 个属性的默认值与 noun 无关，23 个随 noun 变化。目标格式本来就是 `(noun, attr)` 键，
  所以不构成问题——但任何"按属性建全局默认值表"的设计都会在这 23 个上出错。
- 输出必须区分 `verbatim` 与 `derived` 两种来源。老 JSON 没覆盖的 ~3569 个新属性
  只能拿到推导值，不能伪装成权威值。
