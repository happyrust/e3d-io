## 0.5.0 — 2026-10-19

### Added

- Transaction maintains SPAMAP under `SpatialPolicy::Require` by default. `with_spatial(Skip)` removes affected entries when no bounds are available; `with_spatial(Off)` disables spatial maintenance. BOX/CYLI bounds and confirmed member aggregation are built in; other geometric nouns need caller bounds. Existing callers that intentionally omit bounds must explicitly choose Skip or Off. Primitive APIs retain their spatial behavior.
- `Transaction::set_aabb(refno, WorldAabb)`, `StagedSession::spatial()` and `TransactionCommit.spatial` expose caller bounds and spatial reports. Invalid replacement bounds preserve the previous accepted value. `TransactionError::Spatial` carries planning failures; `TransactionError` is now `#[non_exhaustive]`, so downstream exhaustive matches need a wildcard arm. Downstream `TransactionCommit` struct literals must add a `spatial: SpatialReport` field; prefer the report returned by `commit_reporting` when representing an actual commit.
- CLI `apply --spatial require|skip|off` defaults to require. Insert, set and move accept `aabb: [xmin,ymin,zmin,xmax,ymax,zmax]` in world millimetres; six finite numbers with min ≤ max. Existing compatibility invocations must pass `--spatial off`. Reports include spatial differences, including dry-run before rollback.
- Transaction maintains page-1 bucket counters in place, preserving claims and only increasing counters. It syncs page 1 before committing the session through page 0. An I/O failure between these writes can leave raised counters with the previous session visible, skipping numbers; rollback, dry-run, refusal and Moved do not touch page 1. Low-level write primitives do not maintain these counters.

- `Transaction::allocation_basis()` reports the pinned index session/root, counter interpretation or failure reason, and each extent's first allocation. Opening a transaction defers confirmed index-order queries until an extent first allocates. Unconfirmed ordering still performs the eager scan at open.
- Transaction allocation now starts at `max(base index max + 1, page-1 NextAvailable counter)`; reminting uses the pinned merge snapshot and its counter. Newly minted refnos can therefore change. Read refnos from the insertion or commit report instead of predicting them from live elements; pre-minted primitive writes retain their bytes. Missing counters use the index, and malformed or unconfirmed counters report their fallback through `allocation_basis()`. Transaction now raises the physical page-1 counters at commit; primitive write APIs leave them unchanged.
- Read-only `e3d-descriptor next-word1 --db FILE --extent WORD0 [--session N]` compares predecessor and full-scan maxima and reports the current page-1 counter, its interpretation and expected allocation floor.

Read-side seams for the e3d-studio converter and browser (`docs/plans/2026-09-30-e3d-studio-gui-design.md` §4.7, T2). All additive.

- `project_database_paths(root)` is public and re-exported at the crate root: the primary, extensionless databases under a project tree — the candidate set `project_dabacon_tags` reports on — for a caller that lists a project's databases itself. A file root comes back alone and unvalidated; a directory that cannot be listed is still an `Err`.
- `ReadOnlyEngine::extent_paths()` / `PageReader::extent_paths()`: the files a reader reads, as `(extent, path)` in extent order — the primary, the siblings the open attached, and any extent attached by hand. A copy of a database is a copy of exactly these files. A unit test pins a primary, a sibling, a gap and a hand-attached extent.
- `impl Display for DescriptorValue`: the text form of a value. `write::value::parse_value` reads it back, for the attribute it came from, into the same stored words. Reals print as the shortest decimal that parses to the same `f64` (`300`, `1e-7`); references as `=w0/w1` or `nulref`; a word by name when the name hashes back and would not be read as `unset` or a boolean; a text inside `'…'` only where the parser would trim it, unquote it or read `unset`; a string list `|`-separated, or as a JSON array when an item would not survive the split. `tests/value_text_round_trip.rs` covers every decoded row of `ams8000_0001`, `ams5100_0001` and `ams251142_0001`, 149 527 in all: printed, parsed and set back, every record comes out word for word as it was. Formulas, hunk entries, empty arrays and the 87 type-17 arrays the decoder hands over as stored words have no such text; they are counted separately and not set back. `write::value`'s unit tests pin the texts and how they read back.
- `e3d_io::VERSION`: the crate version, for a report that names the reader that produced it.
- `tests/send_sync.rs` asserts what a threaded caller relies on. `ReadOnlyEngine`, `TemplateProvider`, `SchemaPack`, `ElementExtraction` and the error types are `Send`; `AttlibData` and `DbSet` are `Send + Sync`.

### Fixed

- `DbElement::get_number` reads the slot when the body stored under the attribute's negated hash is **neither a whole PML program nor a four-word tuple** — the same rule `extract_attribute` has always applied ("only a body that decodes whole is a formula"). The AVEVA sample's four NOZZ (`/P_S_01/N1` `N2`, `/P_D_01/N1` `N2`) carry a **design-side attribute rule** there for `HEIG` / `POS` / `ORI` — `[0, 2, 10, 1, 106, 2, 897510, 1, 1, 712463, 1601, 1701]`, a two-word header followed by the program `( ATTRIB CDPR NHEI )`. The rule is an annotation; the value it produced is in the slot (`HEIG = 180`, what TTY `Q HEIG` prints and what Core3D's `DECARG -5 → GATRE(HEIG)` draws). Treating it as an unreadable tuple made `HEIG` `Unresolved`, so the catalogue neck `SCYL.PHEI = DDHEIGHT` failed and each nozzle lost its 148–151 mm neck (aps250110 NOZZ 0 / 4 against the E3D RVM; 4 / 4 after).
- `catalogue_pml::parse_number` reads the unit-carrying number record `101 9 <four words> 11 1 1 0` — a literal typed with a distance unit (`20mm`) — where the seven-word `101 6 …` record was the only shape known. The base-plate `SBOX.PXLE = ( ATTRIB OPAR[2 ] + 20 )` and the eaves-haunch `NSEX.PHEI = ( ATTRIB PARA[1 ] + 1 )` were `Unresolved` before; on aps250110 that alone pairs 36 more FIXING against the E3D RVM (2995 → 3039 paired, 1179 → 1215 passed). Any other unit trailer stays unreadable rather than guessed.
- `catalogue_pml::parse_number` also reads the eight-word typed number `101 7 <four words> 11 1` — the same payload, the `11 1` the unit form opens its trailer with, and nothing after it. The AVEVA sample's door catalogue (SFIT `/IS-SRO-NS/900x2045`, 15193/25228) writes every whole-number literal of its jamb and head profiles this way: `SVER.PY = ( ( ATTRIB RPRO WIDT - ATTRIB RPRO DWID - 2 ) * 0.5 + 15 )`, `SVER.PRAD = ( 5 )`, `SVER.PX = ( ( ATTRIB RPRO THK + 1 ) * -1 )`. Unread, those vertices fell back to the all-zero tuple and each 95 × 61 jamb with its 5 mm fillet built as its 35 × 10 door stop alone; E3D's TTY RVM draws `FITTING 1 of STWALL 5 of CWALL /B01_LEV01_INT_WALLS` with the full profile (aps250110: the 57 wall FITT that e3d-model now builds all pair within 0.04 mm). ## 0.4.0 — 2026-09-24

The `Transaction` facade grows into what a project needs on its first day of changing a model, and gets a scriptable front (phase-2 plan T1a–T1d, `docs/plans/2026-09-22-write-path-phase-2-plan.md`): re-parenting and reordering members and editing a group's references (`move_to` / `reorder` / `add_reference_member` / `remove_reference_member`), setting any attribute by name from its text under E3D's own dictionary limits (`set` / `set_hunk` / `with_dictionary`), opening at a base session and merging at commit onto whatever was saved meanwhile — clashes refused by default, refnos the other side took re-minted (`open_at` / `with_on_clash`) — and the `e3d-write apply` CLI that runs one JSON file of instructions as one session, with `--dry-run` and `--report`. A new record starts the way `4CEIL` starts it, and the format word's block counts saturate at `0x3FFF` as `core.dll`'s do — the fix behind a 20 128-member ZONE that E3D listed as 3 744. Two E3D 3.1 gates read it all back: `tools/e3d/write_gate.ps1` (Q0 + 28 questions, now driven by `e3d-write`) and `tools/e3d/alternate_write_gate.ps1` (E3D and e3d-io writing to one ZONE in turn for five rounds). One breaking edge: `MergeOptions` gains `on_clash`, so a literal construction needs `..Default::default()`. 101 test binaries, 622 passed / 0 failed / 30 ignored; the downstream crates (`e3d-model` and its variants) `cargo check` clean against it.

### Added

- `Transaction::move_to(refno, new_owner, at)` — E3D's `INCLUDE`: the record's owner word changes and nothing else in it does, the old owner's member list loses the element, the new owner's gains it at a `MemberPosition` (`Last` / `First` / `After(m)` / `Before(m)`, the positions `REORDER` names), both owners are rewritten in the session so both primaries' claim sessions are bumped. `Transaction::reorder(refno, at)` — `REORDER`: only the owner's list is rewritten. `Transaction::add_reference_member(group, member, at)` / `remove_reference_member(group, member)` edit a reference-list noun's (`GROU`) members, which are references, not children — a child insert under such a noun still changes no list, and a child cannot be moved under one. Refusals, raised before anything is written: `OwnerIsReferenceList`, `NotAReferenceList`, `WouldOwnItself` (the new owner is the element or sits beneath it), `AnchorNotAMember`, `NotAMember`. Member-list changes are queued and applied at staging in registration order; a move withdraws a queued addition to the owner it leaves (so an element inserted and moved in one transaction rewrites only its final owner), and a delete withdraws the element's queued placements. `tests/write_stage6_transaction.rs` (+4): a move rewrites exactly the box and the two ZONEs (`diff` = 3 modified), leaves the box's implicit words, explicit stream and members as stored, bumps both ZONEs' claim sessions and no other; a reorder rewrites only the owner and leaves the member's record at its page and offset; a group's references are edited on the group alone; insert→move and move→delete within one transaction. The E3D gate (`tools/e3d/write_gate.ps1`, `e3d-write-box --move`) asks four more questions — `Q OWNER` of the moved box, `Q MEM` of the ZONE it left (order kept, box gone) and of the ZONE it joined (last), `Q MEM` of the group — and E3D 3.1 answers all of them.
- `Transaction::set(refno, name, text)` — an attribute **by name from its textual form**, on an element inserted in the transaction or one stored: `set(equi, "DESC", "反应堆厂房")`, `set(box, "XLEN", "300mm")`, `set(equi, "POS", "1000, 2000 3000")`, `set(equi, "PURP", "PIPE")` (a word, stored as its base-27 hash), `set(fixing, "BUIL", "true")`, `set(fixing, "NUMB", "42")`, `set(fixing, "ROKEYS", "K1|K2")` (or a JSON array), `set(fixing, "CREF", "/PUMP-1")` (through the `NAME` table) or `"=24384/26484"` or `"nulref"`, anything `"unset"`. The noun's template names the attribute (`TransactionError::UnknownAttribute`) and its descriptor decides the shape (`write::value::parse_value`, `ValueParseError` in `TransactionError::Value` when the text has no reading); `NAME` goes through the rename path. `Transaction::with_dictionary(&Dictionary)` — `write::dictionary`, read from the pack's `catalog/noun_attr_fields.json` (`Dictionary::read` / `from_pack`) — holds every `set` to E3D's own limits before it reaches the record (`TransactionError::Dictionary`): an attribute the dictionary does not have is refused as E3D refuses it (`RATM`, `UNIPAR`: `NotInDictionary`), a text to `SIZE` **characters** as well as the template's byte capacity (`DESC` 120 / 480: `TextTooLong`), an array to `SIZE` elements (`POS` 3, `ROKEYS` 20: `TooManyElements`), a set-once attribute to one setting until it is unset (`UUIDIA`: `SetOnce`), a pseudo attribute to none (`USRWEI`: `Pseudo`); the exception lists `SET_ONCE` / `PSEUDO` are table-driven (`add_set_once` / `add_pseudo`). Without a dictionary `set` checks only what the template says. `tests/write_stage6_set_by_name.rs` (+4): every shape set by name reads back through the descriptors as the value the text names, a `/NAME` reference resolves to the element so named; the five dictionary rules each refuse and nothing refused reaches the file, while the same transaction without the dictionary takes 121 characters; a name set twice in one transaction files the last one only; what cannot be read is refused with the file untouched. The E3D gate (`e3d-write-box --strings`) asks two more questions — an EQUI's `DESC` / `POS` / `FUNC` / `PURP` and a FIXING's `ROKEYS` / `BUIL` / `NUMB` / `CREF` (given as `/NAME`), every one typed as text — and E3D 3.1 prints back exactly what was typed.
- `Transaction::open_at(path, SessionSelector, &mut templates)` — a transaction on any retained session as its **base** (`Transaction::open` is `open_at(Latest)`; `base_sesno()` says which). At commit the file's newest session is compared with the base: the same, the batch is written on top of it as before; moved on — another writer, E3D itself, committed meanwhile — the batch is **merged** the way `core.dll`'s `SAVEWORK` merges (`write_merge_session_with`, now two-phase as `stage_merge_session_with` + `StagedSession::commit`): the three-view conflict scan first (`TransactionError::Conflicts`: 561 a name taken, 562 changed here / deleted there, 590 deleted here / changed there; nothing written), then every update rebased attribute by attribute onto the committed record and written on top of the newest session with `BASESN` = the base. An inserted refno the committed sessions took meanwhile (both sides minted `max + 1` from the same base) is **re-minted** past the newest session's highest, and every owner word, member list, `NAME` key and reference attribute in the batch that named it follows (`TransactionCommit::reminted` has the mapping). Where both sides changed the *same* attribute, owner or reference list of one element to different ends, the facade **refuses** by default — `OnClash::Refuse`, `TransactionError::Clashes(Vec<MergeClash>)` naming each clash (`ClashSite::ExplicitAttribute(hash)` / `ImplicitWord(index)` with the attribute the template places there / `Owner` / `MemberList`), nothing written — rather than let one side win silently; `Transaction::with_on_clash(OnClash::WriterWins)` takes this batch's value, which is plain `SAVEWORK`. Two sides making the same change is no clash, nor is a member-by-member list, whose adds, removes and moves compose. If yet another writer commits between the staging and the page-0 write (`WriteError::Moved`) the facade stages once more on the new newest session before it gives up. `Transaction::commit_reporting` returns `TransactionCommit { report, base_sesno, merged_onto, reminted, retried_after_move }`; `commit_observed` lets a caller see each staging before its page 0 goes in. `MergeOptions` gains `on_clash` (default `WriterWins`, what the primitive path always did) and `WriteError::MergeClashes`; `write::record::three_way_clashes` is the scan, `RecordDraft::replace_member` / `parse_explicit_fields` are public for the re-minting. `tests/write_stage6_merge.rs` (+4): B opened at S commits after A committed S+1 — S+2 is A ∪ B with `BASESN` = S, the diff S+1..S+2 is B alone, B's box re-minted past A's with its `NAME` key and owner list following, A's pages untouched, and a transaction opened explicitly at S after both merges the same way; the same `DESC` (explicit) and `XLEN` (implicit, named through the template) changed on both sides is refused with both clashes named and nothing written, and goes through under `WriterWins` with B's values where they clashed and A's where they did not; 562 / 590 / 561 each refused with the file untouched; a writer dropped in between B's staging and B's page 0 is merged over once (`staged` S+1, moved, `staged` S+2, `retried_after_move`). The E3D gate (`e3d-write-box --merge-from <sesno>`, `write_gate_e3d_saves.mac.template` / `write_gate_merge.mac.template`) has E3D 3.1 itself `NEW EQUI` + `NEW BOX` under the first ZONE and `SAVEWORK` after e3d-io's last session, then a transaction opened at that last session commits a merge onto E3D's session, then E3D reads both back — five more questions, all answered: E3D's BOX as E3D left it, the ZONE listing E3D's EQUI (first — where `NEW` at the owner puts it) and the merged BOX (last, after its anchor), the merged BOX by name / owner / `XLEN` / `POS`, the second ZONE's `FUNC`, and `Q SESSION` = the merge, by e3dio.
- `e3d-write` (`src/bin/e3d-write.rs`) — the batch-instruction CLI over the `Transaction` facade (plan T1d): `e3d-write apply --db <file> --ops ops.json [--schema <dir>] [--base <sesno>] [--on-clash refuse|writer-wins] [--dry-run] [--no-dictionary] [--user U --comment C] [--report report.json]` applies one JSON file of instructions as **one session**. The file is an array, or `{"user", "comment", "ops"}`; an instruction is `insert` (`owner`, `noun`, `name`, `id`, `attrs`, `at`), `set` / `update` (`refno`, `attrs`), `rename`, `delete`, `move` (`refno`, `owner`, `at`), `reorder` (`refno`, `at`), `reference` / `unreference` (`group`, `member`, `at`) — each exactly one facade call (`insert` + `set` per attribute, `rename`, `delete`, `move_to`, `reorder`, `add_reference_member`, `remove_reference_member`); an element is `=24384/26484`, `/NAME` (the base session's `NAME` table, or a name an earlier instruction in the same file bound — an insert's `name` or a `rename`'s new name, so `rename X to /Y` then `set /Y` resolves before the commit; `/*` is the `WORL`) or `@id` (an insert earlier in the same file); `at` is `"last"` / `"first"` / `{"after": e}` / `{"before": e}`; a value is its text (`write::value`'s table) or `{"value": "…", "hunk": true}` to store it as a hunk. E3D's dictionary (`<schema>/catalog/noun_attr_fields.json`) is applied unless `--no-dictionary`; `--base` opens at an older session and the commit is the facade's merge, `--on-clash` its tie rule. The first refused instruction stops the run before anything is written — `op #n (insert BOX under /1RX03-MSUP: XLEN): XLEN = "three hundred": "three hundred" is not a number` — exit code 1 (2 for the command line). `--dry-run` runs the batch through `Transaction::stage` — the shapes, the dictionary, the records laid out, the merge's conflict and clash scan on a moved-on base — and rolls the pages back (`StagedSession::rollback`), leaving the file byte-identical; the sentinel lock is taken for that moment, so a database E3D holds for writing is `Locked` in a dry run as it would be in the commit. `--report` writes one JSON object whether the run succeeded or not: the database, the base and the newest session before the run, every instruction with the elements it resolved to (an insert with `given` and `refno`, which differ when the commit re-minted it, and `taken_in_latest` on a moved-on base), and the `commit` (`written` / `previous` / `appended_pages` / `base_sesno` / `merged_onto` / `reminted` / `retried_after_move`), or `staged` (dry run), or `error` (`op`, `message`). `tests/write_stage6_cli.rs` (+4, running the built binary): the gate's first sessions as one file read back as the instructions said (hunks stored as hunks, `/*`, `@id`, `at`, a Chinese comment and `NAME` from the file, `user` from the file); a dry run leaves the file byte-identical and shows the session number and refnos the commit then uses, on the base and on a moved-on base; fifteen refused instruction files and ten malformed ones each name themselves and write nothing, six command-line mistakes exit 2; `--base` behind the newest session merges, re-mints and reports it, refuses a clash by default and takes it under `writer-wins`, refuses 562.

### Added

#### Write path

- Added element writing to `e3d_io::write` (`write-path` branch, stage 2 of `docs/plans/2026-09-20-dabacon-write-plan.md`): `write_element_session` appends a session that writes new element records and re-points ones that changed, the way `core.dll` does (never editing a page in place — a record is rewritten and the index leaf moved, A2/§4.5). `write::record::RecordDraft` is the inverse of `read_record` + `ParsedElement`: `encode` lays a record out as its eleven-word header, implicit region and the member and explicit blocks contiguously (the order the reader splices a scattered one into), setting the two `(page, packed)` slot addresses and word 10; `from_record_bytes` decodes a gathered record back into a draft so an element can be re-emitted with a member added. Word 10, the storage-format word, is `0x20000000 | member_words | (explicit_stream_words << 14)` — verified against all 6 639 elements of `ams8000_0001` — the low fourteen bits the member list's word count, bits 14..28 the explicit stream's, bit 29 the wide layout every element uses; the reader ignores it (it follows the addresses) but E3D reads it, so it is written the way E3D writes it. `write::index_cow::rewrite_index` edits the RefNo index copy-on-write: it copies every page from the root down to each affected leaf, draws fresh page numbers appended after the previous session, and leaves every other subtree — and its old page numbers — untouched, so `IndexCursor` and `IndexDiff` against the previous session report exactly the change. - Added the `NAME` table reader, `e3d_io::index::named` — the first reader of a dabacon table with variable-width keys — with `ReadOnlyEngine::name_table()` and `ReadOnlyEngine::find_by_name(name)` on top of it. Until now the crate could open a table only if its header stated a fixed `key_dwords` (2 for the refno index, 4 for the reverse-reference tables); the `NAME` table states `0xFFFFFFFF`, which `core.dll` reads as a signed `<= 0` and takes as "each key carries its own length" (`sub_5B00F10` / `sub_5B010F0`, the two routines `3STS` descends with). Its entries are `[key_len][key word × key_len][value × 2]`: the key is the stored name — leading `/`, four bytes to a big-endian word, NUL-padded — and the value a RefNo on a leaf, `(pgno, extno)` on an internal page. The sentinel that opens an internal page is the entry whose *first* key word is `0x80000001`; its length is whatever key it replaced — one word on `ams8000_0001`'s root, seven on `TES6804_0001`'s page 49875, where the six words behind it still spell the tail of the old name — and `core.dll` compares that word as smaller than any other, so the leftovers never take part. Keys order as unsigned words with the shorter of two equal prefixes first, which for names is byte order (a UTF-8 lead byte sorts after ASCII where a signed comparison would put it first); routing is the greatest key at or below the target. `NamedTable::lookup_name` is one descent, `NamedTable::iter` walks the leaves in key order, and a page that is not a `NAME`-shaped table — another table's hash, a fixed key width, an entry running past the used words, keys out of order, a level that does not decrease — is refused with the page number and the reason. `tests/name_table_real.rs` reads `ams8000_0001` (1 834 names) and `ams5100_0001` (221): the walk is strictly ascending, the set of names and the RefNo under each agree one for one with the `NAME` attributes `scan_elements` reads off the live elements, every sampled lookup finds its element within tree-height page reads, and a name that is not there — or the same name in another case — is `None`. - Added `DbSet::with_element_cache_limit(max_entries)` and `DbSet::element_cache_limit()`: the pool-level element cache (`with_element_cache`) can now be given an **entry cap**, counted across every database in the pool. ### Fixed

- Global Database templates now resolve to AVEVA's actual `glbvir.dat` filename. The database/template type reports `GLOB`; mechanically truncating that name produced nonexistent `glovir.dat`, so a `DbSet` resolver could locate `<project>glb` by its header dbnum and still fail before reading the first DB declaration.
- An element whose member list arrives in more than one block no longer loses everything behind it. `parse_tail` took one member block and then looked for explicit blocks, so a second member block stopped the walk: BRAN `24383/85432` in the AMS sample reported **no explicit attributes at all**, `NAME` included, along with the only UDA value it stores. A scan of `ams7999_0001` finds 493 of 29920 elements carrying two or more member blocks, 297 of them with an explicit block behind the cut. The failure was silent in the worst way — "stores nothing" and "the reader stopped early" produce identical output — and it took E3D's own `q att` plus the raw bytes to tell them apart.
- A member list split across blocks no longer drops the RefNo that straddles the boundary or invents one. The list splits mid-RefNo just as an attribute stream does: the first block of that BRAN ends with the word `24383` and the second begins with `85434`, which together are member `24383/85434`. Decoding the blocks separately produced a phantom `85434/0`. The two words after each block header are also skipped unconditionally now rather than only when zero — the same block carries `18010/8193` there, and it was being reported as a member.

- A reference array is now named entry by entry instead of being left waiting on resolution forever. `MBOL.Sbrarray` holds ten slots of which two are filled and E3D prints ` 1 /MSAAD 2 /MSAAG`; `SCOM.Blrfarray` holds one and E3D prints `/MSIDBHP-4-24` bare. Empty slots do not appear, and a position is written only where there is more than one entry to tell apart. Nothing is offered unless every filled slot resolved, so a database the lookup was not given still reads as a reference waiting on a name rather than as a disagreement about the value.
- A TTY heading now reaches its attribute through the catalog's exported query text as well as through the name recovered from `attlib.dat`. The recovery walks the metadata record and takes the first token without whitespace, which for some attributes is an editor label rather than a heading: `BANG` yields `BangleDoubleConverter`, so the `Bangle` rows of `q att` reached no attribute at all, and `Ptdiameter` reached `PTDI` — a different attribute — instead of `PTDM`. `QTXT` is the query text itself and needs no recovery, and no two of the 4271 exported attributes share one.
- `Detref` now resolves to `DETA`. No name source holds that heading: attlib and the catalog both call the attribute `Detail`. Two things say it is `DETA`'s anyway. The rows of `q att` follow the catalog's attribute order exactly for `GPART` and `PRTELE`, and `Detref` lands on `DETA`'s slot in both; and `SPCO.DETA` is a two-word reference in the template, which is what `/AAPA100-SR` has to be read from.
- An attribute the element does not store, whose descriptor gives it a two-word reference slot, now defaults to `Nulref` rather than to the zero of whatever the catalog calls the type. `DETA` is declared `BOOL` against a reference slot, and `q att` prints `Nulref` for a `GPART` that stores nothing.
- An empty word slot now agrees with a zero printed in any unit. Which reading the word holds stays undetermined where attlib has no definition for it, but every reading of an empty slot is zero, and E3D writes that zero with whatever unit the attribute carries: `SCTN.Bangle` prints `0degree`.
- Three stored numbers are no longer taken for a point or a direction on the strength of the count alone. `SCOM.Param` holds `[50, 61.2, TUB]`, which E3D prints as the list it is; the vector reading now applies only where the text is a position or a direction, and anything else falls through to the item-by-item list comparison that the seven-item sibling of that row already used.
- A boolean the element does not store now keeps the default its noun declares. The rule that reads an unstored attribute as its type's zero was recovered from 29 rows of the TTY sample, all of them `WORD` or `STRING`; the one `BOOL` among them, `TABGRO.Fixedb`, goes the other way, so the rule is held to the types it was learned from. Of the 27 booleans the sampled nouns declare `true`, only that one and `CCTA.Activ` — which E3D answers with a sentence about active users — ever reach this path.
- An attribute whose stored word is `0x80000000` or `0x80000001` is now reported as having no value. Those are the two markers `core.dll` checks; the reader had been looking for `0xFFFFFFFF`, which is an ordinary value — `Rlock` stores it and E3D prints -1.
- `logical_count == 0` now reads as an array with no declared upper bound, which is how `sub_5AB5BC0` reads it, instead of as a scalar.
- Storage types 14, 17 and 19 are now always arrays, matching `sub_5AB5BC0`.
- Explicit attribute streams split across Dabacon continuation blocks are now reassembled before decoding.
- Element end-marker detection now skips declared member/explicit blocks, preventing aligned integer `7` values from truncating their payloads.
- Dynamic Dictionary UDA names now resolve from `DYUDNA` when `STUDNA` is empty, including PF fabrication and SCH attributes.
- Dictionary catalog scans now retain per-record read/decode issues and continue instead of aborting the entire catalog.
- Explicit integers with WORD storage semantics now decode to named WORD values (for example `FALS`) even when ATGTDF metadata is absent.
- RefNo fallback scanning now covers concatenated physical extents and rejects small page fields that mimic element headers.
- Element end-marker detection now ignores literal integer `7` values inside the declared implicit region, preventing truncated UDA definitions.
- Element record reads now return `TruncatedRecord` when the end marker is missing instead of silently returning partial data.
- Template payload parsing now rejects truncated walks instead of returning partial templates.
