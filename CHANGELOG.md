# Changelog

## Unreleased

### Added

- Added the `NAME` table reader, `e3d_io::index::named` — the first reader of a dabacon table with variable-width keys — with `ReadOnlyEngine::name_table()` and `ReadOnlyEngine::find_by_name(name)` on top of it. Until now the crate could open a table only if its header stated a fixed `key_dwords` (2 for the refno index, 4 for the reverse-reference tables); the `NAME` table states `0xFFFFFFFF`, which `core.dll` reads as a signed `<= 0` and takes as "each key carries its own length" (`sub_5B00F10` / `sub_5B010F0`, the two routines `3STS` descends with). Its entries are `[key_len][key word × key_len][value × 2]`: the key is the stored name — leading `/`, four bytes to a big-endian word, NUL-padded — and the value a RefNo on a leaf, `(pgno, extno)` on an internal page. The sentinel that opens an internal page is the entry whose *first* key word is `0x80000001`; its length is whatever key it replaced — one word on `ams8000_0001`'s root, seven on `TES6804_0001`'s page 49875, where the six words behind it still spell the tail of the old name — and `core.dll` compares that word as smaller than any other, so the leftovers never take part. Keys order as unsigned words with the shorter of two equal prefixes first, which for names is byte order (a UTF-8 lead byte sorts after ASCII where a signed comparison would put it first); routing is the greatest key at or below the target. `NamedTable::lookup_name` is one descent, `NamedTable::iter` walks the leaves in key order, and a page that is not a `NAME`-shaped table — another table's hash, a fixed key width, an entry running past the used words, keys out of order, a level that does not decrease — is refused with the page number and the reason. `tests/name_table_real.rs` reads `ams8000_0001` (1 834 names) and `ams5100_0001` (221): the walk is strictly ascending, the set of names and the RefNo under each agree one for one with the `NAME` attributes `scan_elements` reads off the live elements, every sampled lookup finds its element within tree-height page reads, and a name that is not there — or the same name in another case — is `None`. The ignored corpus gate walks every `NAME` table under `D:\AVEVA\Projects\E3D3.1`: 1 002 tables, 13 565 455 names, all decoded and in unsigned order — including 168 adjacent pairs a signed comparison would swap, so the order in the files says the same as the code. Stage 2 of `docs/plans/2026-09-20-dabacon-write-plan.md` will maintain this table; the reader is its acceptance side.
- Added the first write path, `e3d_io::write` (`write-path` branch, stage 1 of `docs/plans/2026-09-20-dabacon-write-plan.md`): append a session that changes nothing and commit it the way `core.dll` does (`docs/evidence/2026-09-20-core-dll-dabacon-write-path-algorithms.md` A4–A7). `PageFile` is a read/write handle sized by page 0's `PGSIZE`; `build_session_page` is the inverse of `SessionPage::parse_as` — it copies the newest session page and sets `PREVSP`, `SESNO`, `LASTSP`, `PRISES`, `DATE`/`UDATE`, `USER`, `DESC`, the eight-byte engine tag (`e3dio001`, so a session this crate wrote is recognisable from the page), `BASESN` and `REASON`, carrying `OWNSES`, both tree roots, the table directory and the other tail words over verbatim, and parses the result before handing it out; `stage_empty_session` writes that page at `end + 1` and syncs, and `Staged::commit` re-reads page 0, refuses with `WriteError::Moved` if `LSPGNO` moved meanwhile, then writes page 0 (`LSPGNO` → the new page, `TMPLVN` negated only when still positive, nothing else) and syncs — the two steps are separate so a test can read the file as a crash between them would leave it. `Staged::rollback` truncates the appended page off again. `SessionClock::now(zone_offset)` and `SessionDate::from_unix_seconds` produce the two clocks; text is ASCII-only for now. On the read side only the two offset tables `session::at` and `meta::descriptor::at` became `pub(crate)` (plus a `PRISES` constant), so the writer addresses words through the same constants the readers do. `tests/write_stage1_empty_session.rs` runs the loop on copies of `ams8000_0001` (at session 640 that day) and `ams5100_0001`: the new session reads back through `DbView`, `walk_sessions` grows by one with the old chain unchanged behind it, `diff_sessions(old, new)` is empty, the first elements' record addresses are unchanged, every byte before the old `end` is unchanged except page 0 word 10, the file grows by exactly one type-3 page, the staged-but-uncommitted file still reads as the old session, rollback restores the bytes, and a page 0 rewritten underneath is refused. `tests/common/write_fixture.rs` carries the copy fixture and the two byte-level assertions.
- Added `SessionPage::date` and `SessionPage::utc_date` (`Option<SessionDate>`), closing the `stamp_words` "encoding not closed" note. The four words behind the count at +0x30 are `core.dll`'s `DATE` — `year, month, day * 24 + hour, minute * 60 + second`, the writing machine's local clock — and the four behind the count at +0x64 are `UDATE`, the same instant in UTC with the fourth word in milliseconds (`UTCSES` is that count being 4; E3D 3.1 writes it, 2.1 does not). The split is the one `DB_DB::GetSessionDateTime` hands to `DB_DateTime::set(year, month, hours, milliseconds, kind)`: `DB_TimeSpan::fromHours` for day/hour, `fromMilliSeconds` for minute/second/millisecond. On every retained session of the sample databases the two clocks agree to the second and differ by exactly +28 800 s (425 sessions of 3.1 `ams8000_0001`, all written by the `2_35_23o` engine; the 19 older ones and every 2.1 page state no `UDATE`), and 811 sessions across four files have no chronology inversion. `SessionDate` displays as `2026-09-08T16:22:05.919`, offers `unix_seconds_as_utc()` and `is_plausible()`; `SessionPage::zone_offset_seconds()` is `date − utc_date`. `stamp_words` stays for callers that split the words themselves.
- Added `SessionPage::tail: Option<SessionTail>`, the six words `core.dll` keeps at the end of a session page (+0x7E4..+0x7F8) under the session attributes `RUNUM`, `MEMEXT`, `MEMPPS`, `BASESN`, `REASON`, `LINKPS` (`sub_5AF8740` in 3.1; the same attribute hashes exist in 2.1). `base_sesno` is the session this one was written on top of — the retained session behind it on an unmerged stretch, a folded-away number after MERGE CHANGES, and an *older* number than the retained neighbour when the state was taken back before saving (`ams8000_0001` of 3.1: session 243 on 239 with 242 retained). `reason` is the code `DB_DB::reason` renders through message group 43 as `460 + code`; every plain SAVEWORK sampled states 0 and E3D 3.1's `Saving Meta Data` pages state 15 with no base. `e3d-descriptor sessions` prints the tail; `tests/session_tail_real.rs` walks every retained session of the sample databases.
- Added four read-path counters to `e3d_io::read_stats` — `database_opens`, `scan_calls`, `scanned_elements` and `index_point_lookups` — carried by `snapshot()`, `delta_from()`, `summary()` and `reset()`. They let a caller prove a code path opened N databases and scanned nothing, which is the gate the RefNo-native routing work in gen-model asserts on (`docs/plans/2026-09-12-refno-native-routing-and-lazy-mdb-plan.md`, stage 0).
- Added `DbDescriptor::world_refno()` (`primary_extent_ref / 0`) and `ReadOnlyEngine::world()`, which point-looks the WORLD element up in one B+tree descent and confirms the record is an owner-less `WORL`; an element there that is not a `WORL` is `E3dReaderError::NotAWorld`, `Ok(None)` means the index has nothing at that address. A census over all 1,947 installed E3D 2.1/3.1 primary databases found the WORLD at that address in every element/catalogue/dictionary database; only `COMM`/`MISC`/`SYST` keep it elsewhere. `ElementRecordView::header()` re-reads the eleven-word record header (RefNo, noun, owner) without parsing the attribute stream.
- Added corpus gates that run over every installed database when `E3D_CORPUS_ROOTS` (`;`-separated roots) is set and print a skip otherwise: `tests/refno_dbno_corpus.rs` (`RefNo::dbno()` against every file header, 38,891,013 elements, zero mismatches) and `tests/world_refno_corpus.rs` (`world()` against a full scan per database). Non-ASCII file names in a corpus root are skipped instead of panicking on a byte-boundary `split_at`.

- Added an opt-in, thread-local **element read trace**: `read_stats::trace_element_reads()` opens a scope on the current thread and `ReadTrace::finish()` returns every element that was actually read inside it — `DbElement::parsed` or `DbElement::extraction` ran and returned `Ok` — deduplicated in first-seen order. It answers *which* elements a traversal read, where the counters answer *how many times*: e3d-model uses it to hand back `GenerationOutcome::catalogue_visited`, the catalogue side of one subtree generation, which gen-model checks against its dependency closure (`catalogue_visited ⊆ closure`, ADR-064 D5). Cache hits count as reads (the trace is about the set that was read, not the set that cost I/O); a handle that was minted but never read does not, and neither does a dangling reference whose read failed with `NotFound` — three such refnos in `ams5052_0001` showed up as "elements" of unknown type in the first run and were dropped by moving the record to the success path. Scopes nest and are a stack: an inner scope's reads are recorded in every open scope, so an outer scope still sees everything read during an inner one; dropping a scope without finishing it (the `?` early-return path) pops it without touching the outer ones. When no scope is open the read path pays one thread-local counter load. Also added `DbSet::db_type(dbno)` — the descriptor's `db_type_name()` of an already-registered database, never consulting the resolver — and `DbElement::db_set()`, so a consumer holding only a handle can classify the databases the trace touched.

- Added an opt-in pool-level element cache, `DbSet::with_element_cache()`, and the process-wide read counters behind `e3d_io::read_stats`. Handle-level memoisation was never the whole story: `DbSet::element` mints a fresh handle with an empty `OnceLock` every time, so the repetition that matters happens *inside* `owner()` and `get_element()` — the owner chain that every element walks to its root, and the catalogue chain (`SPRE→SPCO→CATR→SCOM→GMRE`) that every routing member walks to the same few hundred catalogue elements. Measured on `ams8000_0001` through e3d-model's `gen_ams` (6088 design elements, session 264, five catalogue databases): 881 145 record parses and 793 389 descriptor extractions, **145 real reads per element**, 5.9 s of the 6.8 s run. With the cache on, the same run does 11 651 parses and 7 872 extractions — one per distinct element, counting the catalogue side that `visited` does not — in 116 ms, and finishes in 523 ms instead of 6861 ms. `model.obj`, `elements.json` and `report.json` come out byte-identical (SHA-256 unchanged), because nothing about what is read changed, only how many times. The cache is two maps keyed by `RefNo` (which carries its own `dbno`), one for `ParsedElement` and one for `ElementExtraction`, so a navigation-only traversal never pays for descriptor extraction it does not ask for. It is **off by default and unbounded when on**: entries are never evicted, which is right for one bounded subtree and wrong for a long-lived process reading whole databases — that case should build a short-lived `DbSet` instead. `add_db` drops the cached entries of the database it replaces, since replacing a file means moving the timepoint and a retained parse would keep serving the previous session's tree without either side erroring. `read_stats` counts handle hits, pool hits and real reads separately, and times only the real reads; the hit path is one relaxed atomic add, and the two `Instant::now()` calls per miss cost roughly 50–100 ms against the 5.9 s they were measuring.

- Added schema packs for E3D 2.10 and 3.1: one directory per release under `schema/`, carrying all 20 `*vir.dat`, `attlib.dat`, the measured database-tree pair, and the file map. `e3d_io::SchemaPack` plus `--schema` / `--schema-root --e3d-version` keep release-bound files together; explicit file flags still win. Release choice is explicit because none of the investigated database fields is a durable discriminator. Both measured releases have the same `WORL.UPGDNO` values (`amssys=12010401`, `ams8000_0001=12010104`); `DB_DB::setMetaData()` uses `Saving Meta Data.` only as a save comment; and IDA shows `DB_Communication::clearComm()` erases the client/module `COMM.VERS` that `updateVersion()` writes. The diagnostic API reports those values but never maps them to a SchemaPack. Directory names, timestamps and file sizes are ignored. Both releases use tree pair `(7618377, 13387743)`, so the pair remains a family validation rather than a version discriminator.

- Added session-range differencing as one call: `DbView::diff_sessions(from, to)` and `ReadOnlyEngine::diff_sessions` resolve both ends on one walk of the chain, merge the two index roots, and return a `SessionDiff` naming the sessions actually resolved and every RefNo inserted, deleted or rewritten between them. The three pieces — chain walk, two-root differ, record reader — already existed; a caller wanting the increment had to string them together by hand, holding a `DbView` for the diff and a `ReadOnlyEngine` for the records. A range is the net difference of its ends: over the sample databases the keys it names are always a subset of what the retained steps between the ends name, and `ams8000_0001` 1→281 is 6605 insertions as a range against 46 436 changes over 280 steps, because 19 651 elements were created and deleted again along the way. `diff_steps(from, to)` gives that history one retained session at a time.
- Added `changed_elements(&diff)`, which streams a `ChangedElement` per changed key with the record read on each side it exists on. A deleted element's record is still at its old address — the pages of a retained session are never reused — so deletions come with their content: `BOX 24384/26247` of `ams8000_0001`, deleted in session 254, reads back its 204 bytes at session 253's address. Modified means the record was rewritten, not that a value changed — the index compares addresses — so `ChangeKind::Modified { relocated_only }` says when the two addresses hold the same bytes; one of the 54 Modified keys of `ams5052_0001` 163→189 is such a copy. `ams7000_0001` 237→263 rewrites 68 971 records, which is why the records are streamed rather than collected.
- Added `session::ElementDelta`, the template-free comparison of a changed element's two versions: owner, members added / removed / reordered, explicit attributes by hash, and implicit words behind the eleven-word header. `with_attribute_rows` adds the descriptor-decoded rows through the new free function `engine::extract_parsed_element_with_descriptors`, so `FTUB 24384/23262` reads as `POS z 3400 → 2900` rather than as words 17 and 39. Member-list changes are a separate field because they are not attribute rows anywhere: `STRU 24384/26202` gained a member between sessions 250 and 264 and compared as zero rows changed.
- Added `SessionSelector::AtOrBefore(n)`: the newest retained session `<= n`, for a downstream that recorded a watermark `MERGE CHANGES` has since folded away. `ams7000_0001` keeps only sessions 1, 237, 238, 262 and 263, so a watermark of 200 resolves to 1 and re-reports rather than losing the changes of 201..236 that were merged into 237. `Exact(n)` in a hole is refused as before, and `NoSuchSession` now also names the retained sessions either side of the request (`nearest_older`, `nearest_newer`); a backwards range is `SessionError::ReversedRange`, never a silently swapped pair. `ReadOnlyEngine::open_at` takes any selector, not just a number, and goes through `session::resolve` instead of a second resolver of its own.
- Added `e3d-descriptor sessions --db PATH` (the retained chain, newest first) and `e3d-descriptor diff --db PATH --from N [--to N] [--at-or-before on] [--steps on] [--content on] [--limit N] [--desvir PATH --attlib PATH]`, emitting the range or its steps as JSON, with records and deltas under `--content on`.

- Added `point_list`, the decoder for the point runs catalogue wireframe geometry stores for `LINE.Pts`. `1000` closes the list rather than naming a point — every one of the 82 `LINE` elements in `ams7000_0001` ends with it and no list holds it anywhere else — and the hundreds digit of each item picks the letter, so `[1, 100, 2, 1000]` reads as `P1 T0 P2`. A third hundreds block has never been seen and returns nothing rather than a guessed letter.
- Added noun-level default values, read from chunks 1 and 2 of each `*vir.dat` child — the same data `core.dll` loads through `sub_5AF6AB0` mode 1 and returns from `sub_5B03B90`. 10892 of the 35734 descriptors in the 20 shipped schema files state a default; the reader had been taking chunk 0 only. Attributes resolved this way carry the new `TemplateDefault` status, and `emit-attr-info` records the value in a new `descriptor_default` column beside the derived `default_val`.
- Added `StorageShape`, the per-storage-type element geometry recovered from `core.dll`'s runtime width table and confirmed against every descriptor in the schema files. Types 10, 15 and 19 pack four characters to a word and now decode to text; type 9 packs 32 booleans to a word and now decodes to a `BoolArray`; type 14 takes its element width from the descriptor itself; types 18 and 19 had no decode path at all.

### Changed

- Seven comments were corrected against a fresh reading of E3D 3.1 `core.dll`'s write path (the gen-model note `docs/2026-09-20_core-dll-dabacon-write-path-algorithms.md`); no code, test or value changed. **The index leaf's `packed` word**: `sub_5AE9DF0` writes it as `ext | (word_offset << 13)` and `sub_5AE9960` reads it back as `ext = packed & 0x1FFF` (13 bits, the extent the record's page lives in — 1 for the primary file, 0 for an unsaved temp page) and `record = page + 4 * ((packed >> 13) & 0xFFF)` (12 bits of **4-byte** words). This crate's `offset_words = packed >> 12` in 2-byte words lands on the same byte whenever bit 12 is clear (`ext < 4096`), and `flag` is the low 12 bits of that extent — which is why it reads 1 on all 940 694 leaf entries: every sample is single-extent. The adjudication that "refuted bit 13" assumed 2-byte units; in core.dll's units bit 13 is exactly the split. `index/mod.rs` (module doc, `IndexEntry`, `to_page_address`), `index/cursor.rs` (`RecordLoc`, `flag`, `raw_flag`), `index/diff.rs`, `record/block.rs` (`Address`) and `record/mod.rs` say so now, and `refno::PageAddress` names what its two fields really are (`slot_offset` is the extent number, `slot_index` the 4-byte word offset). Inheriting `page.ext` from the index page, as `RecordLoc` does, is therefore right on every sample and would not be on a multi-extent database; that is stated, not fixed. **The width table** `dbl_6453DF8` is readable from the IDB after all: `sub_5AE4A90` fills it from eight `.rdata` literals at `0x5D8B9B0..=0x5D8BA20` plus two `0.5` immediates, and the 24 values (`2:0.5 3:1 4:0.5 5:32 6:0.5 7:1 8:0.5 9:32 10:4 11:0.25 12:0.5 13:0.5 14:1 15:4 16:0.5 17:0.5 18:1 19:4 20:1 21:0.5 22:4 23:4`) agree with the ratios `StorageShape` had fitted from descriptor geometry on every type a descriptor uses; `record/descriptor.rs` carries the table and drops the "not readable from the binary" claim. **Type 19 is not a character run.** It is the stored form of the `std::vector<std::string>` that `db_cxx_put_str_vector` (routine 640, `sub_5AAA8B0` → `sub_5AD5060`) takes: `[item_count] { [index][word_count][byte_length][packed text × word_count] }*`, each string packed four characters to a word behind a 0-based index, its word count and its byte length; `4SCEA` (`sub_5AB7B90`) writes that behind an explicit header of `word_count | 19 << 26`, `sub_5AB4CF0` hands the words back verbatim with a length counted in words, and type 23 is the same value moved into a hunk (paired with 19 the way 21/22/20 pair with 6/10/7). `StorageShape::Characters` still lists 19 and its doc now says the reading is wrong and why it has never shown: every type-19 descriptor (`ROKEYS`/`ROVALS`, `CLAURI`, `DIURIS`, `TADFLT`, `VLOCDE`, `CFGTAV`, …) is unset on every element of the 1 000+ E3D 3.1 databases installed here — 9 421 ROKEYS/ROVALS slots, 116 688 `TABITE.CLAURI`, 6 586 `UDA.TADFLT` — most have no implicit slot at all, and E3D 2.1's templates have no type 19. A list shape for 19/23 waits for a database that carries one.
- The page-0 and session-page layouts are documented word for word against the names `core.dll` serves them under: `meta::DbDescriptor::parse` tabulates all 23 header attributes of the integer table `sub_5AF7C30` (`DBNO`, `EXTID`, `ACCMOD`, `CPYFLG`, `OWNEXT`, `INCON`, `TMPLNO`, `TMPLVN`, `LSPGNO`, `NXTBKT`, `PGSIZE`, `FORMAT`, `EXPIRY`, `CPCNT`, `OCPCNT`, `SUBTYP`, `CLCCNT`, `EXPNG`, `HCCNT`, `NACCNT`, `USERID`, `NOWNEX`, plus `CRINFO`) with the field this crate reads each as or *not read*, and `session::at` tabulates the 24 session-page names of `sub_5AF8740` / `sub_5AF83D0` (`PREVSP`, `SESNO`, `OWNSES`, `LASTSP`, `INDEX`, `CLAIM`, `PRISES`, `DATE`, `TRANSA`, `UDATE`, `USER`, `DESC`, the table directory, the DAB tag, `RUNUM` … `LINKPS`, and the three derived ones `SPGNO` / `PRVSES` / `FRSTSP`). Two readings are flagged as this crate's rather than the product's: +0x30 is `NXTBKT`, the bucket-chain head, which the sampled files happen to point at the oldest session page; and +0x10, carried as `reserved_10`, is `OWNSES`, which is `0xFFFFFFFF` on every sampled page because none is an extract. The README's "Not yet: multi-extent" is gone — `page::io::ExtentSet` has attached `_0002`… since the extent work — and the extract / claim model takes its place.
- Text is decoded by the header's `FORMAT` word instead of by sniffing the bytes. `core.dll` reads `FORMAT` (+0x154) before any string and branches on `== 1` — `db_get_file_session_string` (`sub_5ACECE0`) and the element text paths (`sub_5ABC400`) alike: 1 unpacks the bytes as they lie (`sub_5B8F2D0`), which the UTF-8 API then returns unchanged, so 1 **is UTF-8**; anything else goes through the charset converter (`sub_54B2CE8`) from the project's `MBCHARSET` (`CI-CHI` on a Chinese site) to UTF-8, which is the seven-bit `&~ … &` escaping this crate already restored. The local corpus has both: 451 of 643 databases say 1 (every AVEVA-shipped file and the `acw000` project — `acw5001_0001` holds `梭式泄压阀` as raw UTF-8, 1 719 CJK texts among its first 18 674 elements, no escapes) and 192 say 0 (`ams1112_0001` with 126 045 escapes, the 84 `TES000` files). New: `record::text::TextFormat` (`Utf8` / `Escaped` / `Detect`), `TextFormat::from_header`, `decode_as`; `ParsedElement::parse_as` and a `text_format` field the descriptor decoder reads implicit text under; `explicit::parse_tail_as`; `SessionPage::parse_as`, under which `USER` and `DESC` are now decoded as text rather than cut at the first non-ASCII byte; `ElementDelta::of_as`; `ReadOnlyEngine::text_format` and `DbView::text_format`. Every record and session page read through an engine, a `DbView`, a `DbSet` or the chain walkers now decodes under the header word; `ParsedElement::parse`, `SessionPage::parse` and `ElementDelta::of` keep the old guess for a caller with no header (`TextFormat::Detect`). On the sampled files the header changes no value the guess got right — 14 344 texts of `acw5001_0001`, 3 197 of the 3.1 `ams8000_0001`, 35 269 of `ams1112_0001` agree — and fixes the 78 texts of `ams1112_0001` that are raw GBK with no escape (`B7B4 D3A6 B6D1 B3A7 B7BF` = `反应堆厂房`), which the guess could only read as broken UTF-8: under `Escaped` a stretch between runs is read as the code page and, only when it is not valid GBK, as CP1252 (the converter's own fallback, `sub_54B8E01`). `core.dll` itself shows those 78 as mojibake under `CI-CHI`. `tests/text_format_real.rs` pins the header word of each fixture and the agreement counts.
- `SessionPage::machine` is now `SessionPage::user`, read by its length word. `core.dll` serves +0x7C as the session attribute `USER` with its word count at +0x78 (`sub_5AF83D0`: count at word 30, text from word 31), the same shape as the comment at +0xA0/+0xA4; the old reader took NUL-padded ASCII up to the comment and ignored the count. The values are the login E3D recorded — `dpc`, `80404`, `happyrust`, `YW`, host-shaped `pdms-bj-c103-47` — which is why the field was mistaken for a machine name. A stated count past the nine words that fit before `DESC` is clamped, so a corrupt count cannot read the comment as the user. `e3d-descriptor sessions` prints `user` in place of `machine`.
- `tests/reference_table_real.rs` now decides what a reference table *is* by the criterion `core.dll` implies rather than by a list of attribute names: `db_put_reference` files every edge in the **referring** database under the target, so the referrer half of a 4-dword key is always a refno of the file holding the table. A directory table of that shape whose referrers are not all local is not "who references whom" — `TYPEX` (elements by type) and seven Draft tables (`OCONET`, `MARPTT`, `SYLBTA`, `LSTYNO`, `FSTYNO`, `GLYNO`, `HPATNO`) are the ones the installed corpus holds, and the ignored corpus gate now names any newcomer instead of walking a fixed list: 543 files, 913 reference tables under 58 names, 8 lookalike names. Two more facts are pinned. The point query is a descent, not a scan: on the largest reference table installed, `CATR` of `acp7320_0001` with 744 925 edges, `referrers_of` reads **4 pages** where the walk reads 7 907, and the gate fails if it ever reads more than 16 or more than a hundredth of the walk. And an absent table is not an empty answer: `ams7351_0001`, the largest catalogue installed at 1.2 GB and 3.3 M keys, names only `NAME` and `TYPEX` — no `CATR`, no reference table at all — so a reverse cascade must ask `table_root` first and treat "this database keeps no such table" as its own outcome rather than as "nothing references this". The list of 17 attribute names stays for the tests that want a specific table; it is no longer what tells a reference table from a lookalike.
- `tests/session_l1_contract.rs` no longer states which session `ams8000_0001` is at. It said 264 and latest page 8897; the sample database is live — E3D had written it to 281 and 9277 — and two assertions were red for it. The session number and both descriptor pointers are now compared with the bytes at their offsets, and the chain checks (newest first, strictly descending, ending at 1) hold on a merged file too.
- Tests that read the installed E3D fixtures now check for them at runtime instead of carrying `#[ignore]`. `#[ignore]` hid four failing assertions behind a green `cargo test`, two of which this changelog lists as regressions. ### Fixed

- Global Database templates now resolve to AVEVA's actual `glbvir.dat` filename. The database/template type reports `GLOB`; mechanically truncating that name produced nonexistent `glovir.dat`, so a `DbSet` resolver could locate `<project>glb` by its header dbnum and still fail before reading the first DB declaration.
- An element whose member list arrives in more than one block no longer loses everything behind it. `parse_tail` took one member block and then looked for explicit blocks, so a second member block stopped the walk: BRAN `24383/85432` in the AMS sample reported **no explicit attributes at all**, `NAME` included, along with the only UDA value it stores. A scan of `ams7999_0001` finds 493 of 29920 elements carrying two or more member blocks, 297 of them with an explicit block behind the cut. The failure was silent in the worst way — "stores nothing" and "the reader stopped early" produce identical output — and it took E3D's own `q att` plus the raw bytes to tell them apart.
- A member list split across blocks no longer drops the RefNo that straddles the boundary or invents one. The list splits mid-RefNo just as an attribute stream does: the first block of that BRAN ends with the word `24383` and the second begins with `85434`, which together are member `24383/85434`. Decoding the blocks separately produced a phantom `85434/0`. The two words after each block header are also skipped unconditionally now rather than only when zero — the same block carries `18010/8193` there, and it was being reported as a member.

- A reference array is now named entry by entry instead of being left waiting on resolution forever. `MBOL.Sbrarray` holds ten slots of which two are filled and E3D prints ` 1 /MSAAD 2 /MSAAG`; `SCOM.Blrfarray` holds one and E3D prints `/MSIDBHP-4-24` bare. Empty slots do not appear, and a position is written only where there is more than one entry to tell apart. Nothing is offered unless every filled slot resolved, so a database the lookup was not given still reads as a reference waiting on a name rather than as a disagreement about the value.
- A TTY heading now reaches its attribute through the catalog's exported query text as well as through the name recovered from `attlib.dat`. The recovery walks the metadata record and takes the first token without whitespace, which for some attributes is an editor label rather than a heading: `BANG` yields `BangleDoubleConverter`, so the `Bangle` rows of `q att` reached no attribute at all, and `Ptdiameter` reached `PTDI` — a different attribute — instead of `PTDM`. `QTXT` is the query text itself and needs no recovery, and no two of the 4271 exported attributes share one.
- `Detref` now resolves to `DETA`. No name source holds that heading: attlib and the catalog both call the attribute `Detail`. Two things say it is `DETA`'s anyway. The rows of `q att` follow the catalog's attribute order exactly for `GPART` and `PRTELE`, and `Detref` lands on `DETA`'s slot in both; and `SPCO.DETA` is a two-word reference in the template, which is what `/AAPA100-SR` has to be read from.
- An attribute the element does not store, whose descriptor gives it a two-word reference slot, now defaults to `Nulref` rather than to the zero of whatever the catalog calls the type. `DETA` is declared `BOOL` against a reference slot, and `q att` prints `Nulref` for a `GPART` that stores nothing.
- An empty word slot now agrees with a zero printed in any unit. Which reading the word holds stays undetermined where attlib has no definition for it, but every reading of an empty slot is zero, and E3D writes that zero with whatever unit the attribute carries: `SCTN.Bangle` prints `0degree`.
- Three stored numbers are no longer taken for a point or a direction on the strength of the count alone. `SCOM.Param` holds `[50, 61.2, TUB]`, which E3D prints as the list it is; the vector reading now applies only where the text is a position or a direction, and anything else falls through to the item-by-item list comparison that the seven-item sibling of that row already used.
- A boolean the element does not store now keeps the default its noun declares. The rule that reads an unstored attribute as its type's zero was recovered from 29 rows of the TTY sample, all of them `WORD` or `STRING`; the one `BOOL` among them, `TABGRO.Fixedb`, goes the other way, so the rule is held to the types it was learned from. Of the 27 booleans the sampled nouns declare `true`, only that one and `CCTA.Activ` — which E3D answers with a sentence about active users — ever reach this path.
- An attribute whose stored word is `0x80000000` or `0x80000001` is now reported as having no value. Those are the two markers `core.dll` checks; the reader had been looking for `0xFFFFFFFF`, which is an ordinary value — `Rlock` stores it and E3D prints -1.
- `logical_count == 0` now reads as an array with no declared upper bound, which is how `sub_5AB5BC0` reads it, instead of as a scalar.
- Storage types 14, 17 and 19 are now always arrays, matching `sub_5AB5BC0`.
- Explicit attribute streams split across Dabacon continuation blocks are now reassembled before decoding.
- Element end-marker detection now skips declared member/explicit blocks, preventing aligned integer `7` values from truncating their payloads.
- Dynamic Dictionary UDA names now resolve from `DYUDNA` when `STUDNA` is empty, including PF fabrication and SCH attributes.
- Dictionary catalog scans now retain per-record read/decode issues and continue instead of aborting the entire catalog.
- Explicit integers with WORD storage semantics now decode to named WORD values (for example `FALS`) even when ATGTDF metadata is absent.
- RefNo fallback scanning now covers concatenated physical extents and rejects small page fields that mimic element headers.
- Element end-marker detection now ignores literal integer `7` values inside the declared implicit region, preventing truncated UDA definitions.
- Element record reads now return `TruncatedRecord` when the end marker is missing instead of silently returning partial data.
- Template payload parsing now rejects truncated walks instead of returning partial templates.
