# Changelog

## Unreleased

### Added

- Added element writing to `e3d_io::write` (`write-path` branch, stage 2 of `docs/plans/2026-09-20-dabacon-write-plan.md`): `write_element_session` appends a session that writes new element records and re-points ones that changed, the way `core.dll` does (never editing a page in place — a record is rewritten and the index leaf moved, A2/§4.5). `write::record::RecordDraft` is the inverse of `read_record` + `ParsedElement`: `encode` lays a record out as its eleven-word header, implicit region and the member and explicit blocks contiguously (the order the reader splices a scattered one into), setting the two `(page, packed)` slot addresses and word 10; `from_record_bytes` decodes a gathered record back into a draft so an element can be re-emitted with a member added. Word 10, the storage-format word, is `0x20000000 | member_words | (explicit_stream_words << 14)` — verified against all 6 639 elements of `ams8000_0001` — the low fourteen bits the member list's word count, bits 14..28 the explicit stream's, bit 29 the wide layout every element uses; the reader ignores it (it follows the addresses) but E3D reads it, so it is written the way E3D writes it. `write::index_cow::rewrite_index` edits the RefNo index copy-on-write: it copies every page from the root down to each affected leaf, draws fresh page numbers appended after the previous session, and leaves every other subtree — and its old page numbers — untouched, so `IndexCursor` and `IndexDiff` against the previous session report exactly the change. Because an internal separator is a subtree's least key and `choose_child` routes a key to the child behind the greatest separator at or below it, an inserted key is never below its leaf's minimum and no separator has to move; only page numbers propagate up, a full page splits at the median, and a root that splits grows a new root. The writer reuses the read side's one `IndexNode::decode`, `choose_child` and `cmp_refno` rather than carrying its own (the "one decoder, one router" guards in `tests/index_cursor_real.rs` now name `write/index_cow.rs` as a sanctioned caller). `tests/write_stage2_elements.rs` writes three `BOX`es under a `ZONE` on a copy of `ams8000_0001` and grows the ZONE's member list: `diff_sessions` reports three inserts and one modify, each box reads back through `extract_element_with_descriptors` with the `POS`/`XLEN`/`YLEN`/`ZLEN` written into it, the ZONE lists the three new members in order behind its old ones, the key order and element count hold, and the file changed nothing before the previous session's last page but page 0's commit words. `ElementWrite` is an enum of `Insert`, `Update` and `Delete`: an update rewrites an element's record and re-points its index leaf (`RecordDraft::from_record_bytes` reads a gathered record back into a draft, and `set_real_wide` / `set_explicit_text_ascii` / `push_member` / `remove_member` change it); a delete removes the key from the index and writes no record, so the old bytes stay on disk and `read_element_direct` still reads them at the address they held (§4.5, the page is not reused). `tests/write_stage2_modify_delete.rs` covers both: five `SUBS` each with their `LENG` real and one explicit text changed come back as five modifies whose `ElementDelta` names exactly those two changes, and two leaf elements deleted under one `BRAN` — dropped from its member list too — come back as two deletes and one modify with the deleted keys gone and their old records still readable. Renaming maintains the `NAME` table: `write::named_cow::rewrite_named_table` is the same copy-on-write over the variable-key `NAME` B+tree that `index_cow` is over the fixed-key refno index (reusing `index::named`'s `compare_keys`/`encode_name`; "full" is a dword budget rather than a fixed count, since the keys vary in length), and a `NamedEdit` inserts or deletes a name. `write_element_session` takes `&[NamedEdit]` alongside the element writes and threads the new `NAME` root into the session page's table directory (`NewSession::table_overrides`). A name already in the table is refused as conflict 561 (`NamedCowError::Duplicate` → `WriteError::NameTable`), before any page is written, so a refused write changes nothing. `tests/write_stage2_naming.rs` renames three elements — each `find_by_name` finds the new name in one descent, the old name is gone, and the table still agrees with the elements name for name — names a previously-unnamed element (`RecordDraft::add_explicit_text_ascii` appends the `NAME` attribute the record never had, and the table insert makes `find_by_name` find it), and refuses a fourth element taking a name already in use, leaving the file byte-identical. Multi-write merge begins in `write::merge::write_merge_session`: when the file has moved on since a writer opened it, it aligns three views the way `core.dll`'s `DOPENW` save does — base (the session opened at), latest (the newest committed), and the writer's working changes — and scans base↔latest against the writer's edits for conflicts before writing: 562 a change over a delete, 590 a delete over a change (or a RefNo already taken), 561 a name already in the latest `NAME` table for another element. The merge is written on top of the latest session with its `BASESN` set to the base merged from, so the result is the union of both writers, and two writers editing one element are reconciled attribute by attribute: `write::record::three_way` rebases the writer's change onto the committed record — from the committed record, taking only the implicit words, explicit attributes and members the writer actually changed relative to its base — so edits to different attributes compose and an edit to the same attribute is the writer's (A3b's plain-`SAVEWORK` rule; `extract flush`, which gives the committed side, is not implemented). The scan runs before any page is written, so a refused merge changes nothing. Member lists reconcile the way A3b.4 does (`sub_5B1FF60`/`sub_5B20CA0`): `write::record::member_list_diff` walks the writer's base and working lists with two cursors and says what the writer added, removed and moved — a member in both lists at different places is one move of whichever member `core.dll`'s distance rule finds further displaced, so `[p q r s]` → `[q r s p]` is one move of `p`, not three — and `merge_members` replays those edits onto the committed list in the writer's order: a removal takes the member out, an addition goes in right after its anchor, and a move takes the member out of wherever the committed side has it and puts it back after the same anchor — the nearest member before it in the writer's list that the merged list still holds (the "preceding shared sibling"), or the front when none does. So two writers adding members to one owner both land, each after its own anchor; a member both sides moved sits where the writer put it; a move whose anchor the other side removed falls back to the sibling before that; and a moved member the other side took out of the list stays out. `RecordDraft::move_member_after` is the REORDER edit for callers. `tests/write_stage3_merge.rs::a_moved_member_lands_after_its_anchor_when_merged` runs it on a 126-member `ZONE` of `ams8000_0001`: A appends a box, B (based on S) moves the first member behind the last, and the merged list is exactly the base list rotated with A's box still behind it. A noun whose members are references rather than children merges its list whole instead (`sub_5B1F660`): `core.dll` reads that off word 3 of the noun's template header, and a survey of the 20 shipped schema files shows the word is 0 on nouns that own nothing, 1 on nouns whose members are their children, and 2 only on `GROU` (design and catalogue), `MDB` and `USLI` (system) — the reference-list nouns. `record::template::MemberListKind` types it on `NounTemplate::member_list_kind`; `write::record::three_way_with` takes a `MemberMerge` (`MemberByMember`, or `WholeList`, where the writer's whole list replaces the committed one if the writer changed it at all and the committed list stands otherwise); and `write_merge_session_with` takes `MergeOptions { templates }` — hand it the schema's `TemplateProvider` and a `GROU` merges whole, while `write_merge_session` without one merges every noun member by member. `a_reference_list_noun_merges_its_members_whole` builds `WORL → GPWL → GROU` on the copy (no shipped database has a `GROU`), has two writers each add a zone to the group, and gets B's whole list with the schema at hand and both additions without it. A merge is also de-duplicated (A3a's `sub_5B07080`): if the merged record turns out equal to the committed one — two writers converged on the same value, or a change was undone — `RecordDraft::content_eq` catches it (comparing noun, owner, members, the implicit region past its header and the explicit attributes as fields, so header words and stream padding do not count) and the update is dropped, leaving the leaf pointing at the record already on disk and writing no copy. `tests/write_stage3_merge.rs` runs the plan's construction — C0 at session S, writer A commits S+1, writer B merges as S+2 — checking that disjoint changes are A∪B, that two changes to one element's different attributes both survive, that two writers adding members to one owner both keep their members, that a merge converging on the committed value appends only its session page and diffs empty, and that a change over a delete (562), a delete over a change (590) and a name already taken (561) are each refused with the file left as A committed it. Not yet: CLAIM, the extract-flush variant of the whole-list overwrite (which skips the overwrite when the committed side changed the list too), and a record that splits across pages.

- The element write path now writes a **record whose tail blocks do not fit on one page**, splitting them into the page-linked segments the reader already gathers. A record is an eleven-word header, an implicit region, and up to two tail blocks (the member list and the explicit stream); the header and implicit region are one contiguous run the index leaf points at and the reader reads off the one page, so they still cannot span (a header-plus-implicit longer than a page is `WriteError::RecordTooLong`, which no longer means the whole record) — but each tail block is now laid down as one or more segments, a segment filling to the page boundary and stating in its header the `(page, packed)` where the rest continues, exactly the link `record::gather` follows (`record::block::continues_at`). `write::place_record` and `place_block` replace the old placement that bump-packed a whole record onto one page and refused anything larger; the header's two slots are back-patched to where each block's first segment landed, so the record reads back whole however many pages it took — including the case where the member block spills off the start page and the explicit block after it lands on a continuation page, whose address is back-patched into the start page after it was set aside. `record::wide_format_word` and `RecordDraft::explicit_stream_words` are shared by the placer and `RecordDraft::encode`. `tests/write_stage2_crosspage.rs` grows a `ZONE` on `ams8000_0001` to two thousand members — a member block several pages long — and reads back every member in order (a record the writer failed to split would come back from the reader as `BlockOverflowsPage`, so a clean read is the proof), and writes a fresh element with a 1 500-member list followed by a `DESC` text to exercise the spilled-member-then-explicit back-patch; both read back whole and the range diff sees exactly the one change.

A type-19 value is `[n] { [i][words][bytes][packed text × words] }*` — a 0-based item index, the item's packed word count and byte length ahead of each string — stored under a header of `19 << 26 | words` with **no** separate count word (the reader's `case 19` copies `words` words verbatim), and the length `sub_5AD5060` reports for it is `1 + Σ(4 × words_i + 3)`; an empty vector reaches `4SCEA` as length 0, which unsets the attribute. A hunk is a **seven-word directory entry** in the explicit stream, `[hash][type << 26 | 5][1][page][packed][count][words]` (the five data words are one type-11 element, four words wide: the first block's `(page, packed)` in the index-leaf encoding, the element count the caller stated, the payload's length in words), with the value in a **kind-3 block chain** whose header is the five tail-block words plus the attribute hash and the hunk type — `[3:u16][words:u16][refno.0][refno.1][cont.0][cont.1][hash][type]` — filling to the page boundary and continuing like a member or explicit block (minimum segment: header plus two words, `sub_5AE9DF0`'s `a6 = 9`); `4SCEA` writes the hunk into the current output page before the record is laid down. - Added the `NAME` table reader, `e3d_io::index::named` — the first reader of a dabacon table with variable-width keys — with `ReadOnlyEngine::name_table()` and `ReadOnlyEngine::find_by_name(name)` on top of it. Until now the crate could open a table only if its header stated a fixed `key_dwords` (2 for the refno index, 4 for the reverse-reference tables); the `NAME` table states `0xFFFFFFFF`, which `core.dll` reads as a signed `<= 0` and takes as "each key carries its own length" (`sub_5B00F10` / `sub_5B010F0`, the two routines `3STS` descends with). Its entries are `[key_len][key word × key_len][value × 2]`: the key is the stored name — leading `/`, four bytes to a big-endian word, NUL-padded — and the value a RefNo on a leaf, `(pgno, extno)` on an internal page. The sentinel that opens an internal page is the entry whose *first* key word is `0x80000001`; its length is whatever key it replaced — one word on `ams8000_0001`'s root, seven on `TES6804_0001`'s page 49875, where the six words behind it still spell the tail of the old name — and `core.dll` compares that word as smaller than any other, so the leftovers never take part. Keys order as unsigned words with the shorter of two equal prefixes first, which for names is byte order (a UTF-8 lead byte sorts after ASCII where a signed comparison would put it first); routing is the greatest key at or below the target. `NamedTable::lookup_name` is one descent, `NamedTable::iter` walks the leaves in key order, and a page that is not a `NAME`-shaped table — another table's hash, a fixed key width, an entry running past the used words, keys out of order, a level that does not decrease — is refused with the page number and the reason. `tests/name_table_real.rs` reads `ams8000_0001` (1 834 names) and `ams5100_0001` (221): the walk is strictly ascending, the set of names and the RefNo under each agree one for one with the `NAME` attributes `scan_elements` reads off the live elements, every sampled lookup finds its element within tree-height page reads, and a name that is not there — or the same name in another case — is `None`. - Global Database templates now resolve to AVEVA's actual `glbvir.dat` filename. The database/template type reports `GLOB`; mechanically truncating that name produced nonexistent `glovir.dat`, so a `DbSet` resolver could locate `<project>glb` by its header dbnum and still fail before reading the first DB declaration.
- An element whose member list arrives in more than one block no longer loses everything behind it. `parse_tail` took one member block and then looked for explicit blocks, so a second member block stopped the walk: BRAN `24383/85432` in the AMS sample reported **no explicit attributes at all**, `NAME` included, along with the only UDA value it stores. A scan of `ams7999_0001` finds 493 of 29920 elements carrying two or more member blocks, 297 of them with an explicit block behind the cut. The failure was silent in the worst way — "stores nothing" and "the reader stopped early" produce identical output — and it took E3D's own `q att` plus the raw bytes to tell them apart.
- A member list split across blocks no longer drops the RefNo that straddles the boundary or invents one. The list splits mid-RefNo just as an attribute stream does: the first block of that BRAN ends with the word `24383` and the second begins with `85434`, which together are member `24383/85434`. Decoding the blocks separately produced a phantom `85434/0`. The two words after each block header are also skipped unconditionally now rather than only when zero — the same block carries `18010/8193` there, and it was being reported as a member.

- A reference array is now named entry by entry instead of being left waiting on resolution forever. `MBOL.Sbrarray` holds ten slots of which two are filled and E3D prints ` 1 /MSAAD 2 /MSAAG`; `SCOM.Blrfarray` holds one and E3D prints `/MSIDBHP-4-24` bare. Empty slots do not appear, and a position is written only where there is more than one entry to tell apart. Nothing is offered unless every filled slot resolved, so a database the lookup was not given still reads as a reference waiting on a name rather than as a disagreement about the value.
- A TTY heading now reaches its attribute through the catalog's exported query text as well as through the name recovered from `attlib.dat`. The recovery walks the metadata record and takes the first token without whitespace, which for some attributes is an editor label rather than a heading: `BANG` yields `BangleDoubleConverter`, so the `Bangle` rows of `q att` reached no attribute at all, and `Ptdiameter` reached `PTDI` — a different attribute — instead of `PTDM`. `QTXT` is the query text itself and needs no recovery, and no two of the 4271 exported attributes share one.
- `Detref` now resolves to `DETA`. No name source holds that heading: attlib and the catalog both call the attribute `Detail`. Two things say it is `DETA`'s anyway. The rows of `q att` follow the catalog's attribute order exactly for `GPART` and `PRTELE`, and `Detref` lands on `DETA`'s slot in both; and `SPCO.DETA` is a two-word reference in the template, which is what `/AAPA100-SR` has to be read from.
- An attribute the element does not store, whose descriptor gives it a two-word reference slot, now defaults to `Nulref` rather than to the zero of whatever the catalog calls the type. `DETA` is declared `BOOL` against a reference slot, and `q att` prints `Nulref` for a `GPART` that stores nothing.
- An empty word slot now agrees with a zero printed in any unit. Which reading the word holds stays undetermined where attlib has no definition for it, but every reading of an empty slot is zero, and E3D writes that zero with whatever unit the attribute carries: `SCTN.Bangle` prints `0degree`.
- Three stored numbers are no longer taken for a point or a direction on the strength of the count alone. `SCOM.Param` holds `[50, 61.2, TUB]`, which E3D prints as the list it is; the vector reading now applies only where the text is a position or a direction, and anything else falls through to the item-by-item list comparison that the seven-item sibling of that row already used.
- A boolean the element does not store now keeps the default its noun declares. The rule that reads an unstored attribute as its type's zero was recovered from 29 rows of the TTY sample, all of them `WORD` or `STRING`; the one `BOOL` among them, `TABGRO.Fixedb`, goes the other way, so the rule is held to the types it was learned from. Of the 27 booleans the sampled nouns declare `true`, only that one and `CCTA.Activ` — which E3D answers with a sentence about active users — ever reach this path.
- An attribute whose stored word is `0x80000000` or `0x80000001` is now reported as having no value. Those are the two markers `core.dll` checks; the reader had been looking for `0xFFFFFFFF`, which is an ordinary value — `Rlock` stores it and E3D prints -1.
- `logical_count == 0` now reads as an array with no declared upper bound, which is how `sub_5AB5BC0` reads it, instead of as a scalar.
- Storage types 14, 17 and 19 are now always arrays, matching `sub_5AB5BC0`.
- Explicit attribute streams split across Dabacon continuation blocks are now reassembled before decoding.
- Element end-marker detection now skips declared member/explicit blocks, preventing aligned integer `7` values from truncating their payloads.
- Dynamic Dictionary UDA names now resolve from `DYUDNA` when `STUDNA` is empty, including PF fabrication and SCH attributes.
- Dictionary catalog scans now retain per-record read/decode issues and continue instead of aborting the entire catalog.
- Explicit integers with WORD storage semantics now decode to named WORD values (for example `FALS`) even when ATGTDF metadata is absent.
- RefNo fallback scanning now covers concatenated physical extents and rejects small page fields that mimic element headers.
- Element end-marker detection now ignores literal integer `7` values inside the declared implicit region, preventing truncated UDA definitions.
- Element record reads now return `TruncatedRecord` when the end marker is missing instead of silently returning partial data.
- Template payload parsing now rejects truncated walks instead of returning partial templates.
