2 · encoded_location 的位切分

bit 31                    20 19                     0
    +-----------------------+------------------------+
    |   bool bit index      |      word offset       |
    +-----------------------+------------------------+
      raw >> 20               raw & 0x000FFFFF
取值含义
word offset > 0属性住在 implicit 区第 n 个字
word offset == 0不在 implicit 区——去 explicit 尾巴按 hash 找。这是有效状态，不是缺数据
bool bit index仅 storage_type_code 为 5 或 9 时有意义；> 31 视为越界

3 · compact 还是 wide

format_word = implicit_data[word 10]
layout = (format_word & 0x2000_0000) ? WIDE : COMPACT
选错不会报错。compact 用 f32、wide 用 f64，两列的 word offset 从第一个 浮点属性开始就会岔开，而且越往后差得越多。BRAN 的 HBOR 在 compact 列是 33 字、wide 列是 45 字。 读到的是别人的字节，不是异常。

两列要么都有位置、要么都是 0。全库 35734 条描述符里，compact 与 wide 的非零 offset 数量完全相等。

5 · 数组的字节形状

wide 下的 type 6，logical_count = 3，storage_words = 7：

  +0   count            (= 3)
  +1   v0 低 32 位   \
  +2   v0 高 32 位   /  Fortran 字交换：拼的时候两半对调
  +3   v1 低
  +4   v1 高
  +5   v2 低
  +6   v2 高

1 + 3 × 2 = 7 —— 和描述符声明的 storage_words 对得上。

实测：BRAN 的 HPOS 在 word 14–15 存 1EB851EC 40C0B345， 对调后 0x40C0B3451EB851EC = 8550.54。不对调算出来是垃圾数。

7 · *vir.dat 容器

层规则
页2048 字节 = 512 个大端 u32（Fortran "DB,BL 512"）
page 0[0] magic 必须是 6；[2] 库类型 hash；[5] noun 数；[7] child 数组首 token
child 条目7 dword：hash + 三组 (token, size)。按 hash 排序，二分查找
分块读每页前 511 个字是数据，第 512 个字是下一页的 Fortran token（1-based）
noun payload[1][2] 回显 noun hash；[9] 描述符条数；[14] 起按 stride 走
校验位[11] == 14 + Σstride。游走跑飞了当场发现

token 是 1-based：page_no = token - 1。

校验位实测：WORL 14 + 7×10 = 84，盘上 0x54； BRAN 14 + 1074 = 1088，盘上 0x440。两个 noun 独立对上。
